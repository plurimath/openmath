= OpenMath

OpenMath 2 (the published standard) and OpenMath 3 (the draft) as a typed
Ruby model: parse the XML encoding, serialize it back, and evaluate through
content dictionaries. Part of the {plurimath}[https://github.com/plurimath]
ecosystem; consumed by the plurimath gem.

== Status (0.1.0)

The complete OpenMath 2 object grammar — OMOBJ, OMS, OMV, OMI, OMB, OMSTR,
OMF, OMA, OMBIND, OMBVAR, OME, OMATTR, OMATP, OMFOREIGN, OMR — modeled with
{LutaML Model}[https://github.com/lutaml/lutaml-model] against the
authoritative schema (`schemas/openmath2.rnc`, vendored from
OpenMath/OMSVN). Namespaced documents parse in both the unprefixed and the
`om:`-prefixed form; round trips are byte-stable.

Known limitations (tracked in the issues):

* OpenMath 3 is scaffolded, not modeled — its versioned hierarchy lands
  with the draft revision it implements (plurimath#582).
* Root-element and schema validation are roadmap work; the reader is
  lenient about unknown roots.
* Non-OpenMath markup inside OMFOREIGN is not yet represented.

== Usage

[source,ruby]
----
require "openmath"

object = Openmath.parse(<<~XML, version: 2)
  <OMOBJ xmlns="http://www.openmath.org/OpenMath">
    <OMA><OMS cd="arith1" name="plus"/><OMI>1</OMI><OMI>1</OMI></OMA>
  </OMOBJ>
XML

object.oma_value.first.omi_value.map { |i| i.value.first.strip }
# => ["1", "1"]

puts object.to_xml
----

== Roadmap

The semantic program: content dictionaries bind symbols to evaluated
operations (the Plurimath PM-series evaluator), the official CD collection
loads as data, and the test suites of other implementations join the
{plurimath-testsuite}[https://github.com/plurimath/plurimath-testsuite]
under the provenance discipline. Tracked in plurimath#582 (the gem),
#583 (evaluation), #584 (the testsuite stage), #585 (the wiring).
